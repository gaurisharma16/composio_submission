OAuth2 Dominates — But With a Catch

62% of apps use OAuth2 as their primary auth. However, OAuth scope complexity varies wildly — Salesforce requires a "Connected App", LinkedIn Ads requires a Marketing Developer Program application, and Google Ads requires separate developer-token approval on top of OAuth. Composio's OAuth dance must handle all variants.

Finance & Enterprise = Gated Wall

9 out of 10 Finance apps (Plaid production, Ramp, Brex, PitchBook, Paygent, iPayX, Amazon SP-API) are either gated behind enterprise contracts, compliance review, or US-entity requirements. This is the single category where agent tooling cannot self-serve its way to production.

Easy Wins: Dev Tools & Productivity

Categories 7–8 (Developer/Infra + Productivity/PM) are self-serve goldmines. GitHub, Vercel, Cloudflare, Supabase, Notion, Linear, ClickUp — all have free tiers, simple PAT auth, and excellent docs. Agent toolkits here are buildable in hours. 7 official MCP servers already exist in this zone.

#1 Blocker: No Webhooks or Webhooks Poorly Documented

Across all 100 apps, the single most common buildability blocker is missing or poorly documented webhooks — affecting Notion, Harvest, LinkedIn Ads, and 8+ others. Without webhooks, agents must poll, adding latency and burning through rate limits.

AI/Research Category Has the Most Dead Ends

Category 10 (AI/Research) has the highest HITL rate — 7 out of 10 apps (NotebookLM, Otter AI, Fathom, Consensus, Devin, higgsfield, Grain) are either waitlisted, behind paid plans, or have no public API at all. The honest finding: saying so is the correct answer, not a failure.

MCP Adoption is Early but Accelerating

Only 7 of 100 apps have an official MCP server (GitHub, Cloudflare, Supabase, Slack, Twenty, Firecrawl, Devin). Another 4–5 have community-built MCPs. This is the most significant emerging pattern — apps with MCPs can be integrated by AI agents with zero custom code.

Step 2 — The Agent
What Was Built & How It Works

A Python pipeline using Composio SDK + Gemini AI to automate research, with a deterministic HITL fallback for gated apps.

1

Composio SDK Initialised

The agent uses Composio(api_key=...) to create a named user session via sessions.create(user_id="research_agent"). This provisions a Composio tool context. The SDK exposes tools to the LLM automatically.

2

Gemini 1.5 Processes Each App

For each of the 100 apps, Gemini is prompted to extract: auth method, access type, API surface, webhook support, and buildability verdict — outputting structured JSON validated by a Pydantic model.

3

HITL Fallback Triggered Automatically

If Gemini's confidence is low, the output fails schema validation, or the app matches known gated patterns (enterprise-only, no public docs), the agent sets hitl_needed: true and writes an agent_note explaining why human verification is needed.

4

Human Cross-Checks 10% Sample

A stratified 10-app sample was manually verified against live docs. Results are recorded in the Verification section below. Accuracy is measured and discrepancies noted honestly.

5

Results Written to agent_results.json

All 100 structured records — including evidence URLs, HITL flags, MCP availability, and self-serve detail — are saved and loaded dynamically into this dashboard.
